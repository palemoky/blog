## 解释器与JIT

![](imgs/index-1782432900913.webp)

JIT技术适用于动态语言和跨平台语言，如Java和Python。静态语言则主要依赖编译期优化。

JIT通过对执行代码计数（计数结果保存在内存中，重启进程后归零），获得热点代码，然后将热点代码的机器码缓存，省去每次字节码到机器码的编译过程，从而实现加速的目的。

由于JIT需要统计热点代码，因此这段时间感受不到JIT带来的性能提升。

是否采用JIT，对应了餐厅的两种出餐模式：

- 热门菜品：使用备好的食材快速出餐
- 临时点单：现场准备原材料加工

PHP 7 的 OPcache 是缓存所有代码的字节码，PHP 8 的JIT则是缓存热点代码的机器码，所以 PHP 8 在运行计算密集型任务时性能提升明显。

Go 和 Node.js 都采用了三色标记的 GC 算法，但 Go 为了保持 GC 的简洁性，没有像 V8 那样实现分代收集。

操作系统中的线程会共享堆内存而不共享栈内存，但 V8 为了避免前端开发者面对多线程数据竞争的问题，通过 Isolate 隔离了各线程的堆内存，使得运行时只能通过序列化与反序列化在不同线程间传递数据。因此，改用 Go 实现时，可以直接共享堆内存数据，充分发挥多核并行的优势。

V8 的 Isolate 使线程在行为上非常接近进程，但比进程更轻量，线程间通信也更简便，因此没有直接采用多进程方案。

值得注意的是，V8 的 Isolate 与 Python 的 GIL 在效果上都避免了数据竞争，但设计初衷和实现机制截然不同：Isolate 服务于 JS 的单线程执行模型，数据竞争的消除是其自然结果，靠的是**内存隔离**——每个 Isolate 拥有独立的堆，线程间无法直接共享 JS 对象；GIL 则主要是为了简化 CPython 的内存管理（引用计数），靠的是**全局互斥锁**——线程间共享内存，但同一时刻只允许一个线程执行 Python 字节码，避免数据竞争更多是副作用。前者多个 Isolate 可以真正并行，后者的多线程在 CPU 密集型任务上本质仍是串行。
